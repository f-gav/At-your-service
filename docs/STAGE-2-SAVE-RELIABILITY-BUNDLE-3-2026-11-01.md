# Этап 2 · Пакет №3 — надёжность сохранения и восстановления черновиков

**Дата:** 1 ноября 2026. Все изменения — клиентские (frontend) и автоматические тесты. Рабочая Supabase и игровые правила не изменяются.

## Найдено и исправлено

- [x] Восстановление устаревшего локального черновика намеренно заблокировано после редактирования с другого устройства (CAS). Однако пользователь до сих пор не видел сохранённые правки и не мог получить их без ручного доступа к localStorage. Создан `DeviceDraftNotice`: обнаружение черновика другой облачной версии и скачивание локального JSON для ручного сравнения, **без автоматического слияния и без отправки данных на сервер**.
- [x] При смене версии персонажа или параллельном редактировании двумя вкладками новый черновик перезаписывал единственный локальный ключ. Теперь до замены сохраняется отдельная архивная запись в локальном хранилище (индивидуальная версия/вкладка); старые архивы очищаются по сроку 14 дней. При ошибке архивации запись не затирается.
- [x] Обычная печать одним редактором **не создаёт архив на каждый символ**: владелец записи задаётся для экземпляра редактора.
- [x] Ранее код молча поглощал отказ localStorage (private browsing, quota): экран мог обещать «Черновик сохранён на устройстве», хотя сохранение не удалось. Теперь хук `useAutoSave` различает локальный успех/ошибку и показывает отдельное предупреждение без блокировки облачного сохранения.
- [x] Ошибка первоначальной загрузки персонажей выглядела как «пустой список», оставляя кнопку создания доступной. Теперь есть состояние `characterLoadError`, явная ошибка с повторной загрузкой, запрет создания из состояния неопределённого списка. Отказ promise обрабатывается без unhandled rejection.
- [x] `PathfinderSheet`, `ProjectMoonSheet` и универсальный редактор показывают одинаковую информацию о локальных резервах и проблемах записи.
- [x] Оптимистическая проверка `updated_at` (CAS) сохранена; ошибки записи не проглатываются, редактор не покидается при несохранённых правках.
- [x] Добавлены тесты архивирования, смены устройства, запрета повреждения предыдущего черновика при отсутствии места, отказа сети, последовательной отправки и восстановления.
- [x] Новый Chromium сценарий воспроизводит незавершённый запрос во время новых правок, отказ сети, ручной retry, CAS conflict, запрет выхода и скачивание сохранённого на устройстве JSON.

## Важные ограничения

Черновики живут исключительно в localStorage браузера и потому не являются полноценной резервной копией. Данные в скачанном JSON чувствительные — хранить файл приватно. Само скачивание **не загружает файл обратно автоматически**: для ручного сравнения значений. Политика 14-дневного срока сохраняется. Автоматического слияния конфликтов, влияющего на игровые правила, нет.

Продакшн БД, Security Definer RPC, RLS, Auth, Storage и игровые формулы/механики не изменялись. Отложенное требование Rooms V2 — один персонаж принадлежит только одной комнате — не затронуто. Не объявлять прошедшими двухаккаунтный JWT E2E и реальный DB+Storage restore из этапа 1 до фактической проверки.
