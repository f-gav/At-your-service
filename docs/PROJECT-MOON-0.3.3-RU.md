# Project Moon — контрольная точка 0.3.3: оружие и приёмы

**Цель:** предотвращать удаление без подтверждения и случайное изменение соседней карточки. Игровые механики и экспорт JSON v1 не изменяются.

## Проверенные проблемы

1. **Приёмы удалялись немедленно.** Кнопка корзины напрямую фильтровала `skills` без подтверждения; заполненные поля терялись по одному нажатию.
2. **Изменение приёма было привязано к индексу.** После удаления соседней карточки позднее событие богатого текстового редактора могло попасть на изменившийся индекс вместо исходного приёма.
3. **Позиция карусели оружия после удаления** вычислялась с опорой на длину списка до обновления. Теперь используется явная функция расчёта безопасного смещения с учётом числа оставшихся карточек.

## Исправления

- Диалог подтверждения оружия повторно используется для приёмов; название удаляемого приёма и предупреждение видны до подтверждения. Отмена или Escape не меняют лист.
- `updateMoonSkill` и `removeMoonSkill` изменяют запись только по её стабильному `id`. Если к удалённому ID приходит поздний callback, он ничего не делает; названия, описания, Light, EP, ранг и тип соседних приёмов сохраняются.
- `moonOffsetAfterWeaponRemoval` ограничивает индекс карусели доступным диапазоном после удаления.
- Существующие подтверждение для оружия, сохранение состояния переключателя анимации, и минимум из двух слотов оружия сохранены.
- Верхний предел 100 приёмов — **технический предел чтения уже существующей схемы**, а не игровое ограничение шести приёмов. В этом патче не менялся.
- Открытые черновики сохраняются существующим механизмом `useAutoSave`. Дополнительные схемы Supabase и изменения игровых формул не требуются.

## Регрессия

`tests/project-moon-weapons.mjs` проверяет удаление средней карточки, сохранение IDs и текста оружия, запрет изменения чужого приёма поздним callback, подтверждение удаления, сохранение после JSON round-trip и смещения карусели. Общий `npm run test:models` дополнительно проверяет четыре страницы Project Moon, совместимость, JSON, автосохранение, PWA и предыдущие изменения.

## Не закрытые вопросы

- Кросс-девайсный конкурентный ввод в один и тот же лист не покрыт этим патчем.
- Резервное восстановление 0.2.2 и межаккаунтные E2E остаются открытыми.
- Механики затрат Light и EP, количество игровых приёмов и формулы не изменялись.
