# JSON персонажей — первая версия

Каждый персонаж может быть скачан отдельно через «••• → Экспорт JSON». В разделе «Мои персонажи» доступен импорт одного JSON. Импорт создаёт **нового** персонажа, не перезаписывая старого. Все записи проходят обычную Supabase RLS и принадлежат вошедшему пользователю.

Формат файла:
```json
{
  "system": "Pathfinder",
  "format": "at-your-service-character",
  "version": 1,
  "character": {
    "name": "Пример",
    "details": {
      "pathfinderSheet": {
        "name": "Пример",
        "ancestry": "Эльф",
        "character_class": "Некромант",
        "schemaVersion": 1
      }
    }
  }
}
```

Поля system в первой строке: Pathfinder, DnD либо VtM. Export доступен всем текущим системам. **Import пока поддерживает только Pathfinder**; для других систем вернётся понятное сообщение, данные не изменятся. Новые форматы вводить через version и проверять по версии.

В JSON нет пользовательского ID, имени Google-аккаунта, времени сохранения, RLS-параметров, прав или порядка карточек. При импорте ID/владелец/позиция назначаются заново, чтобы файл можно было передавать другому пользователю. JSON принимает только известную версию и ограничен 2 МБ; поля не исполняются как код.

Аватарки хранятся отдельно в Supabase Storage, а при экспорте включаются в JSON как два необязательных оптимизированных WebP (см. раздел ниже).

## Совместимость с динамическими полями PF2e

Новые поля, добавленные через админ-панель, хранятся под стабильными ID в `details.pathfinderSheet`. Экспорт JSON v1 не фильтрует этот объект по встроенному набору полей, поэтому пользовательские поля и значения удалённых из макета полей сохраняются при экспорте/импорте. Для этого исправления менять версию JSON не требуется; добавлена регрессионная проверка сохранения и повторного открытия.

## Изменения интерфейса: героизм, выпадающие меню и ЧБ (2026-10-10)

- У каждого героя `hero_1`, `hero_2`, `hero_3` сохраняются как boolean, как раньше. Вместо галочки меняется только визуальное представление — заливка шестиугольника.
- Новый тип поля `select` задаёт варианты **в схеме шаблона** (`options: string[]`), а выбранный вариант хранится в `details.pathfinderSheet[fieldId]` как обычная строка. Это совместимо с JSON версии 1.
- Если импортированное или ранее сохранённое значение больше не присутствует в списке вариантов, оно остаётся видимым и не стирается автоматически.
- Переключатель «Черно-белый лист» — только локальная настройка браузера (`localStorage`), не поле персонажа. В JSON она не экспортируется.
- Формат `at-your-service-character` и `version: 1` **не изменяются**.

## Портреты персонажей (обратная совместимость)

Файлы портретов хранятся отдельно от значений листа и не копируют частные Storage URL в экспорт. Начиная с этой версии **необязательное** поле `character.portrait` содержит два встроенных сжатых WebP в виде `data:image/webp;base64,...` (`card` и `sheet`). При импорте их загружают в приватное хранилище уже нового владельца. Ранее созданные JSON без `portrait` продолжают работать. Версия формата остаётся `1`, размер JSON ограничен 2 МБ. Все другие поля листа PF2e остаются неизменными.

## Визуальные параметры полей (2026-10-10)

Новый необязательный признак `underline: true` сохраняется **в шаблоне администратора**, а не в `character.details.pathfinderSheet`. Это декоративная линия и на данные поля не влияет. Экспорт/импорт JSON персонажа версии 1, включая портреты, остаётся прежним; миграция файлов не требуется.

## Портрет: один файл и две независимые обрезки (2026-10-10)

Формат `version: 1` остаётся прежним: новый необязательный `character.portrait` содержит `source` (один WebP, data URL) и `crops.card / crops.sheet` (нормализованные `x,y,w,h` от 0 до 1). Старый формат `{card, sheet}` импортируется для обратной совместимости. JSON без портрета тоже поддерживается. Текстовые поля, ID и расположение шаблона PF2e не изменились.

## Форма нажимных полей

В шаблоне администратора у `kind: "toggle"` теперь могут присутствовать `toggleShape`, `toggleMode`, `toggleInsetX` и `toggleInsetY`. Они задают только внешний вид (форма и геометрия заливки) и **не экспортируются в JSON персонажа**. В `details.pathfinderSheet` значение остаётся boolean, как раньше. JSON версии 1 не требует миграции и сохраняет обратную совместимость.
