# JSON персонажей — актуальный формат v2

С октября 2026 года экспорт создаёт **JSON v2**. Импорт по-прежнему принимает
старые файлы **v1**, поэтому архивы не требуют ручного преобразования.
Изменение формата экспорта не изменяет сохранённые записи в Supabase.

## Как устроен v2

```json
{
  "system": "Pathfinder",
  "format": "at-your-service-character",
  "version": 2,
  "character": {
    "name": "Граций",
    "details": { "notes": "" },
    "sheet": {
      "fields": { "level": "1", "ability_int": "+4", "pf2e_notes_content": "..." },
      "page": { "layout": "alternative", "order": "1,2,3,4,notes", "notesEnabled": true },
      "spells": {
        "mode": "library",
        "selection": [{ "id": "pf2e-necromancer-create-thrall", "prepared": true }],
        "layout": { "version": 1, "items": [
          { "kind": "spell", "id": "pf2e-necromancer-create-thrall", "zone": "cantrip" }
        ] },
        "classes": ["necromancer"],
        "traditions": ["occult"]
      }
    }
  }
}
```

- `details` содержит общие заметки/данные персонажа, `sheet` — только его
  лист. Для Project Moon в `sheet` сохраняется объект Project Moon с
  `fields`, `weapons`, `skills`, `notes` и дополнительными настройками.
- `fields` содержит игровые значения под постоянными ID; глобальный шаблон
  листа и позиции полей по-прежнему **не экспортируются**. Пользовательские
  ID из редактора шаблонов сохраняются, даже если приложение о них не знает.
- Для PF2e заклинания и размещение теперь записываются структурированными
  массивами/объектом, а не строками с вложенным JSON. Позиции заклинаний,
  которых больше нет среди подготовленных, исключаются; разделители остаются.
- **Только в библиотечном режиме** исключаются старые дублирующие текстовые
  таблицы (`cantrip_names`, `cantrip_actions`,
  `spellbook_left_names` и родственные поля). В ручном текстовом режиме они
  сохраняются. Если библиотека ещё не использовалась, данные старого
  текстового листа также сохраняются.
- Все остальные неизвестные значения сохраняются сознательно: без текущей
  схемы пользовательского шаблона нельзя безопасно определить, являются ли
  они удалёнными полями или данными будущих версий.
- Экспорт с карточки перед формированием JSON повторно читает персонажа из
  Supabase. При наличии совместимого несохранённого локального черновика он
  не выдаёт заведомо устаревшую копию, а просит сперва сохранить лист.
- Импорт v2 преобразует структурированный `sheet` во внутреннюю модель,
  которую понимают оба представления PF2e и Project Moon. Импорт создаёт
  отдельную карточку, не изменяя уже существующую. Портрет и ограничения
  размера (2 МБ для файла и 50 000 символов данных листа) остаются прежними.

## История формата: v1 (для совместимости)

Ниже сохранено описание исходного JSON v1. Оно относится к старым экспортам
и к внутреннему формату сохранения отдельных полей, **не к новому v2**.

# JSON персонажей — первая версия

Каждый персонаж может быть скачан отдельно через «••• → Экспорт JSON». В разделе «Мои персонажи» доступен импорт одного JSON. Импорт создаёт **нового** персонажа, не перезаписывая старого. Все записи проходят обычную Supabase RLS и принадлежат вошедшему пользователю.

Формат файла:
```json
{
  "system": "Pathfinder",
  "format": "at-your-service-character",
  "version": 1,
  "character": {
    "name": "Пример",
    "details": {
      "pathfinderSheet": {
        "name": "Пример",
        "ancestry": "Эльф",
        "character_class": "Некромант",
        "schemaVersion": 1
      }
    }
  }
}
```

Поля `system` в корне: `Pathfinder`, `DnD`, `VtM` либо `Project Moon`. Экспорт предусмотрен для всех систем. **Импорт поддерживает Pathfinder и Project Moon (Pr. Moon)**; для пока неготовых DnD и VtM возвращается сообщение об отсутствии импорта. Новые несовместимые форматы вводятся через поле `version`.

В JSON нет пользовательского ID, имени Google-аккаунта, времени сохранения, RLS-параметров, прав или порядка карточек. При импорте ID/владелец/позиция назначаются заново, чтобы файл можно было передавать другому пользователю. JSON принимает только известную версию и ограничен 2 МБ; поля не исполняются как код.

Аватарки хранятся отдельно в Supabase Storage, а при экспорте включаются в JSON как два необязательных оптимизированных WebP (см. раздел ниже).

## Совместимость с динамическими полями PF2e

Новые поля, добавленные через админ-панель, хранятся под стабильными ID в `details.pathfinderSheet`. Экспорт JSON v1 не фильтрует этот объект по встроенному набору полей, поэтому пользовательские поля и значения удалённых из макета полей сохраняются при экспорте/импорте. Для этого исправления менять версию JSON не требуется; добавлена регрессионная проверка сохранения и повторного открытия.

## Изменения интерфейса: героизм, выпадающие меню и ЧБ (2026-10-10)

- У каждого героя `hero_1`, `hero_2`, `hero_3` сохраняются как boolean, как раньше. Вместо галочки меняется только визуальное представление — заливка шестиугольника.
- Новый тип поля `select` задаёт варианты **в схеме шаблона** (`options: string[]`), а выбранный вариант хранится в `details.pathfinderSheet[fieldId]` как обычная строка. Это совместимо с JSON версии 1.
- Если импортированное или ранее сохранённое значение больше не присутствует в списке вариантов, оно остаётся видимым и не стирается автоматически.
- Переключатель «Черно-белый лист» — только локальная настройка браузера (`localStorage`), не поле персонажа. В JSON она не экспортируется.
- Формат `at-your-service-character` и `version: 1` **не изменяются**.

## Портреты персонажей (обратная совместимость)

Файлы портретов хранятся отдельно от значений листа и не копируют частные Storage URL в экспорт. Начиная с этой версии **необязательное** поле `character.portrait` содержит два встроенных сжатых WebP в виде `data:image/webp;base64,...` (`card` и `sheet`). При импорте их загружают в приватное хранилище уже нового владельца. Ранее созданные JSON без `portrait` продолжают работать. Версия формата остаётся `1`, размер JSON ограничен 2 МБ. Все другие поля листа PF2e остаются неизменными.

## Визуальные параметры полей (2026-10-10)

Новый необязательный признак `underline: true` сохраняется **в шаблоне администратора**, а не в `character.details.pathfinderSheet`. Это декоративная линия и на данные поля не влияет. Экспорт/импорт JSON персонажа версии 1, включая портреты, остаётся прежним; миграция файлов не требуется.

## Портрет: один файл и две независимые обрезки (2026-10-10)

Формат `version: 1` остаётся прежним: новый необязательный `character.portrait` содержит `source` (один WebP, data URL) и `crops.card / crops.sheet` (нормализованные `x,y,w,h` от 0 до 1). Старый формат `{card, sheet}` импортируется для обратной совместимости. JSON без портрета тоже поддерживается. Текстовые поля, ID и расположение шаблона PF2e не изменились.

## Форма нажимных полей

В шаблоне администратора у `kind: "toggle"` теперь могут присутствовать `toggleShape`, `toggleMode`, `toggleInsetX` и `toggleInsetY`. Они задают только внешний вид (форма и геометрия заливки) и **не экспортируются в JSON персонажа**. В `details.pathfinderSheet` значение остаётся boolean, как раньше. JSON версии 1 не требует миграции и сохраняет обратную совместимость.

## PF2e: ранг владения и автоматические показатели

В `details.pathfinderSheet` теперь может присутствовать необязательное поле `rulesMode`: `"auto"` или `"manual"`. Старые персонажи без него остаются в ручном режиме, если у них уже заполнен лист. Значения рангов остаются строками `"0"`–`"4"` под **старыми ID** `skill_*_rank`, `save_*_rank`, `perception_rank`. Поля результатов `skill_*_total`, `save_*`, `perception` и составляющие `*_ability`/`*_prof` записываются в знакомые поля после автоматического расчёта. При импорте файл не нуждается в миграции: формулы пересчитывают их в режиме auto. Формат JSON по-прежнему `version: 1`. Удалённые из админ-шаблона поля остаются сохранёнными.

## Pathfinder патч №2: боевые параметры

Новые ключи в \`details.pathfinderSheet\` начинаются на \`combat_\` и хранят выбранное снаряжение, настройки отдельных вычислений и значения бонусов. Поля \`armor_class\`, \`armor_dex\`, \`armor_prof\`, \`armor_item\`, \`shield_broken\`, \`hp_max\`, \`weapon_1_attack\`…\`weapon_5_damage\` используют **прежние ID**. Они становятся вычисляемыми только при общем режиме \`rulesMode: "auto"\` и включённом флажке своего раздела. Сохраняются уже вычисленные значения, но при повторном открытии они пересчитываются. ПЗ текущие, временные, ПЗ щита и другие исходные поля никогда не переписываются без прямой команды пользователя (например, «Блок щитом»).

Совместимость: JSON формата \`version: 1\` остаётся прежним, новые ключи необязательны, старые импортируются без конвертации. В экспорте нет отдельных URL или секретов. Калибровка/позиции шаблона и поля портретов не менялись.

## Project Moon (Pr. Moon) — экспорт и импорт

Для Pr. Moon используется **тот же JSON v1**, что и для Pathfinder, но с
`"system": "Project Moon"` и отдельным объектом
`character.details.projectMoonSheet`. В нём сохраняются:
имя в `character.name`, `fields`, `autoVitals`,
`smoothWeaponSwitch`, `maxOverrides`, `pageOrder`, `weapons`,
`skills` и `notes`. Изменения глобального опубликованного шаблона
доступны через редактор листов, а **не** через JSON конкретного игрока.

Скачивание — `••• → Экспорт JSON` на карточке Pr. Moon; загрузка —
`Импортировать JSON персонажа` на главной странице. Импорт создаёт
нового героя без перезаписи исходного. При наличии портрета он включается
в виде одного встроенного WebP `source` с отдельными кадрами
`crops.card` и `crops.sheet`. Ранее экспортированные пары
`card`/`sheet` по-прежнему читаются.

Ограничения остаются общими: файл до 2 МБ; данные `details`
после нормализации до 50 000 символов; приватная загрузка портрета
при импорте выполняется от имени текущего пользователя. Сам JSON
не содержит Supabase ID и пользовательских секретов.
