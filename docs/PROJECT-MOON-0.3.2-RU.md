# At your service! — Project Moon 0.3.2: утверждённые решения и патч

**Статус:** реализация утверждённых решений; итоговая приёмка — по GitHub Actions последнего SHA.

## Утверждено пользователем

1. **Атака — ручной ввод.** Поле `projectMoonSheet.fields.attackBonus` редактируется и сохраняется как обычная строка в существующей схеме JSON v1. Значение `+Rank` отображается **только в подсказке** и не записывается в поле. Формула из Community Rulebook 3.x не изменена.
2. **Приёмы — без игрового ограничения до 6.** Допускается расширение списка; остаётся технический верхний предел хранения 100 записей, уже существовавший в модели данных. Приложение не должно разрешать 101-ю запись, которая потеряется после перезагрузки. Существующие приёмы не переименовываются и не удаляются.
3. **Состояния — только ручное управление.** Добавлены пояснения по ST=0 / SP=0 / HP=0. Никакие значения ресурсов и статусы не меняются автоматически.
4. **Light — `3 + Rank` плюс ручной максимум.** Существующая формула, `maxOverrides.light` и кнопка сброса без изменений. Не вводится искусственный верхний предел 5, поскольку ранги и свойства экипировки могут влиять на максимум.
5. **Сопротивления — необязательный калькулятор.** По нажатию раскрывается отдельная панель; пользователь вводит итог атаки и добавочный урон после сопротивления, выбирает тип урона. Результат показывается отдельно для HP и ST по формуле `итог × сопротивление + дополнительный урон`, не округляется автоматически и **не списывается** из персонажа. Коэффициенты Fatal ×2 / Weak ×1.5 / Normal ×1 / Endured ×0.5 / Ineffective ×0.25 / Immune ×0. Все поля калькулятора временные и не сохраняются в JSON.

## Тесты

`tests/project-moon.mjs` проверяет ручную атаку, сохранность поля при сериализации, уровни и числовые множители сопротивлений, независимый расчёт урона, неподдерживаемый ввод и персонажа с более чем шестью приёмами. Существующая общая регрессия проверяет совместимость JSON v1, портретов, автосохранения, PWA, PDF и других игровых листов.

## Не делаем без нового согласования

- Автоматическая трата Light или списание HP/ST/SP из калькулятора.
- Навязывание лимита из шести Skills, автоподбор эффектов или вычисление EP.
- Автоматические эффекты паники, ошеломления или кровотечения.
- Изменение формул базовых HP/ST/SP/Light, правил оборудования и округления урона.
- Миграции Supabase и изменения существующих JSON-полей.

**Отдельные открытые требования 0.2:** резервное восстановление 0.2.2 и межаккаунтные E2E остаются открытыми.
