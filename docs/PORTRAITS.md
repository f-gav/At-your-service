# Портреты персонажей — единый источник и два независимых кадра

## Текущая система (10 октября 2026)

- Входные изображения: JPG/PNG/WebP до 3 МБ. Исходник не загружается в Supabase в первоначальном формате.
- Два независимо настраиваемых кадра: квадрат карточки и вертикаль PF2e.
- В браузере готовится **один WebP, содержащий всю картинку**, длинная сторона не больше 1280 px, целевой размер не более **350 КБ** (фактический размер зависит от изображения).
- В базе `characters.portrait_source_path` хранит путь к этому WebP; `characters.portrait_crops` содержит нормализованные прямоугольники (x, y, w, h) для `card` и `sheet`.
- Эти прямоугольники обрезают одну исходную картинку исключительно при отображении. Отдельные файлы для двух видов больше не создаются.
- Хранилище остаётся **приватным**: доступ к портрету имеют только пользователи, которым принадлежит соответствующий персонаж; Storage RLS проверяет ID владельца и ID персонажа.
- Поля бланка PF2e и координаты администратора не связаны с портретами.
- Портрет по умолчанию для PF2e: `public/pathfinder/portrait-placeholder.webp`.

## Совместимость

- Новые JSON-файлы содержат `character.portrait: {source: "data:image/webp;base64,...", crops: {card: {x,y,w,h}, sheet: {x,y,w,h}}}`.
- JSON версии 1 с прежней парой `{card, sheet}` по-прежнему импортируется. Такие импорты временно используют старую пару файлов, а при следующей загрузке нового изображения преобразуются в единый источник.
- JSON без портрета тоже остаётся совместимым.
- Уже существующие старые файлы остаются отображаемыми благодаря `portrait_card_path` и `portrait_sheet_path`, пока пользователь не заменит портрет.
- При замене нового изображения старые файлы удаляются после успешной смены путей в БД.
- В JSON **нет путей Supabase**, владельца или подписанных URL. JSON по-прежнему версии 1.
- Общий лимит импорта JSON — 2 МБ.

## Важные файлы

- `src/features/portrait/crop.ts` — кадрирование и оптимизация одной картинки.
- `src/features/portrait/PortraitEditor.tsx` — центральный редактор с двумя независимыми рамками.
- `src/features/portrait/PortraitImage.tsx` — применение кадрирования к одной картинке в обоих видах.
- `src/features/portrait/portrait-storage.ts` — приватная загрузка, удаление и совместимость старых изображений.
- `src/features/portrait/portrait-json.ts` — экспорт/импорт обеих разновидностей JSON.
- `supabase/migrations/20261010_one_source_portrait_with_crop_frames.sql` — новые поля таблицы и разрешённое имя `-source.webp` в Storage RLS.

## Оставшиеся проверки

Нужно вручную проверить загрузку на мобильных устройствах, изменения обоих кадров, экспорт и повторный импорт JSON. Также в будущем стоит разрешить повторное кадрирование уже загруженного файла без повторного выбора его на устройстве.
