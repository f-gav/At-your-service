# Портреты персонажей · At your service!

## Поведение

- На карточке персонажа и на **третьей странице PF2e** доступно отдельное нажатие на портрет. Открывается центральное модальное окно.
- JPG / PNG / WebP до 3 МБ; обрезка с раздельными настройками для квадрата (карточка) и вертикального портрета (лист).
- Перемещение мышью или пальцем; масштабирование ползунком и колёсиком мыши.
- Два WebP генерируются **локально в браузере**: квадрат 384×384, вертикаль 480×708. Макс. 400 КБ каждый, с адаптивным уровнем качества.
- По умолчанию у PF2e используется `public/pathfinder/portrait-placeholder.webp` из приложенного пользователем силуэта.
- Смена и удаление поддерживаются; новые имена файлов при смене исключают конфликт CDN-кэша.

## Архитектура

- `src/features/portrait/{crop.ts,PortraitEditor.tsx,PortraitEditor.css}` — независимый визуальный редактор.
- `src/features/portrait/portrait-storage.ts` — загрузка, удаление, подписанные ссылки и обновление записи персонажа.
- `src/features/portrait/portrait-json.ts` — перенос **изображений** внутри экспортируемого JSON, без передачи чужих Storage-путей.
- `characters.portrait_card_path` / `portrait_sheet_path` — только пути к личным файлам. Поля листа в `details` не затрагиваются.
- Приватный bucket `character-portraits`, Storage RLS по текущему `auth.uid()` **и** принадлежности конкретного персонажа. Используется обычный publishable ключ.
- Для новых загрузок два пути с случайным идентификатором, затем атомарное обновление ссылки на оба пути в базе. Старые файлы удаляются после успеха.
- При удалении персонажа файлы удаляются перед удалением записи (пока действует owner/RLS).

## JSON и совместимость

**Формат версии 1 сохранён**. Необязательное `character.portrait: {card: "data:image/webp;base64,...",sheet:"..."}` добавляется при экспорте только при наличии портрета. Внутри файла **нет ссылок и идентификаторов Supabase Storage**, поэтому при импорте в другой аккаунт создаются новые приватные объекты. Старые JSON без `character.portrait` продолжают импортироваться. Для импорта нового изображения из JSON лимит увеличен с 1 до 2 МБ.

## Следующие улучшения

- Поддержка редактирования уже загруженного исходника без повторной загрузки (сейчас сохраняются только два оптимизированных кадра).
- Периодическая серверная очистка сиротских файлов, если удаление старых объектов завершилось ошибкой.
- E2E проверки на Safari/iOS/Android и реальное пользовательское тестирование загрузки, crop и Storage RLS.
- Не смешивать вложенные портреты с экспортом схемы полей административного редактора.

## Исправление доступа к Storage — 2026-10-10

Первая версия Storage RLS ошибочно использовала `storage.foldername(name)` внутри вложенного `exists(select ... from public.characters c ...)`. PostgreSQL связывал имя `name` с `c.name` (имя персонажа), поэтому все загрузки получали `new row violates row-level security policy` даже для владельца. Во всех трёх политиках `SELECT`, `INSERT` и `DELETE` теперь явно указано `storage.objects.name`. Путь `user_id/character_id/nonce-card.webp` и `nonce-sheet.webp` проверяется и остаётся приватным. При повторном создании базы используется также исправленный исходный скрипт миграции. Отдельная миграция `20261010_fix_character_portrait_rls.sql` предназначена для ранее установленного варианта.

Данные персонажей и версия JSON не затронуты.

## Визуальная полировка портретов

- Серый силуэт PF2e в карточке увеличен и сдвинут вниз. Стили применяются **только** к изображению по умолчанию: пользовательские квадратные кадры остаются как обрезаны при загрузке.
- В листе PF2e кнопка портрета немного уменьшена и отодвинута от краёв печатной рамки. Это корректировка CSS, значения персонажа и кадры в Storage не меняются.
- Исходный PNG (как и JPG) после обрезки **не сохраняется в Storage**: браузер создаёт два WebP — 384 × 384 и 480 × 708, каждый до 400 КБ. Один персонаж использует до 800 КБ под оба кадра; на практике обычно меньше. Прозрачность WebP поддерживается. Пользователю не нужно конвертировать PNG вручную.
