# Этап 3 — пакет №1 из 5: границы App и операций с персонажами

Дата: 1 ноября 2026. База: `main` после этапа 2. PR #74.

## Что переработано

- Редактор простого чернового листа (`CharacterEditor`) вынесен из `App.tsx` в `features/character/CharacterEditor.tsx`, включая восстановление локального черновика и автосохранение.
- `SiteLogo` и `HeroEmblem` вынесены в `components/SiteBranding.tsx`, исходные CSS-классы и ассеты сохранены.
- Чистые операции создания начального состояния PF2e и Project Moon, порядка персонажей, независимого копирования полей и нормализации подтверждённых данных выделены в `features/character/character-operations.ts`.
- Все обычные запросы к таблице characters вынесены в `features/character/character-repository.ts`: загрузка, создание, чтение перед JSON-экспортом, CAS-сохранение, удаление и атомарная перестановка через RPC.
- `App.tsx` остаётся координатором состояний, авторизации, экранов, портретов, JSON и навигации. Прямых `from('characters')` в UI больше нет.
- Сохранён существующий `saveCharacterIfCurrent` с CAS по `updated_at`, проверками `user_id` и отказом от потери локальных данных при конфликте.

## Проверка и контракты

- Новый `tests/stage3-app-boundaries.mjs` проверяет независимые операции, отсутствие прямых запросов characters в App, ограничения по user_id, CAS и RPC.
- Обновлены старые регрессионные проверки, которые считывали перенесённые компоненты по прежним именам файлов: черновики, брендинг, Project Moon и портретные запросы.
- Полный GitHub Actions CI остаётся обязательным: TypeScript/Vite, модели, Android-адаптивность на тестовых ширинах, Chromium PDF, Pathfinder, Project Moon, библиотека, PWA, Rooms, PostgreSQL, Windows, сохранение и публикация.
- Внешний вид, игровые правила, форматы JSON, PDF, схема БД, RLS и production-данные не менялись.
