# Rooms V2 — этап 4, пакет 2/5 (2026-11-02)

## Подтверждённые риски
1. Параллельные `roomDetailRequests` завершались в произвольном порядке: старый ответ мог перезаписать актуальные снимки или броски.
2. После ухода из комнаты незавершённый запрос мог обновлять её данные.
3. Обрыв WebSocket / фоновая вкладка полагались только на 8-секундный polling без немедленной сверки при восстановлении соединения.

## Исправления
- Последняя запущенная загрузка обзора / комнаты получает монотонный номер. Состояние меняет только ответ последнего запроса.
- Идентификатор активной комнаты отдельно сверяется перед установкой участников и бросков. Cleanup эффекта инвалидирует старые запросы и очищает список при выходе.
- На `SUBSCRIBED`, `online` и возвращение активной вкладки запрашивается свежий серверный снимок.
- Периодический опрос не отправляется из скрытой вкладки; установленные слушатели снимаются при очистке эффекта.
- Тест `tests/stage4-rooms-realtime.mjs` встроен в обязательный CI.

## Не изменено
Production Supabase, таблицы, RLS, RPC, механика бросков, схема JSON, экспорт PDF и разрешённая ранее модель multi-room.

## Ограничения и следующий пакет
Это проверка логики синхронизации на уровне исходного кода плюс полный текущий CI, но не двухаккаунтный production E2E. Пакет 3/5 — интерфейс и полномочия мастера, управление участниками.
